# GrabLine 1.32.1

This patch addresses download failures, truncated captured videos, torrent startup,
resume speed spikes, and the downloads table at the minimum window size.

- Direct downloads send a resource validator on every ranged segment. If a server
  ignores ranges or returns HTTP 412/428, GrabLine stops the parallel workers,
  discards the partial ranges, and retries with one ordinary GET. It never joins
  bytes from the old and new responses.
- GrabLine owns torrent scheduling instead of competing with libtorrent's internal
  queue. Resuming also clears stale per-torrent rate limits, including when the new
  limit is unlimited.
- Resumed tasks retain their saved byte baseline. Aggregate throughput counts only
  changes in jobs present in both samples, and smoothing resets if a counter falls.
- At narrow widths, the downloads table keeps name, progress, speed and status on
  screen. Size and ETA remain available in the detail drawer and return as columns
  when the window is widened. Explicit column preferences are preserved.
- Captured YouTube CDN playback URLs are resolved through the originating video
  page, allowing the media engine to fetch full formats instead of one playback
  chunk. Missing media fragments now fail the download instead of producing a
  misleading completed clip.

The release includes Chrome and Firefox extension ZIPs alongside the desktop
installers and SHA-256 checksums. Store submissions are separate from these packages.

## Verification

1. Retry a failed direct download. A server refusing ranged requests should fall
   back to a single stream; compare the resulting file's checksum when available.
2. Resize to 940 × 560 and select a download. Name, progress, speed, status and the
   drawer's controls should remain accessible. Widen the window to restore size/ETA.
3. Add a well-seeded magnet, wait for metadata, then pause and resume it. Progress
   should continue without a speed spike representing bytes already on disk.
4. Update/reload the browser extension, play a YouTube video, and capture it from the
   popup or player. The quality picker should refer to the original video. Verify
   that the saved video's duration matches the source and that it has audio.

The original failing URLs were unavailable. Regression coverage reproduces the
HTTP failure modes, browser handoff, resume counters, and minimum-width layout;
local libtorrent seed-to-client transfers cover both torrent files and magnets.
A magnet still needs reachable peers, and a download still needs valid site access.
