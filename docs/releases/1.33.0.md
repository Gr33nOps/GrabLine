# GrabLine 1.33.0

This release makes GrabLine one connected family: your phone and your other PCs
appear in a new **Devices** page, and each can see and control the others.
It also gives the desktop app the same look as GrabLine for Android and the website.

## Devices page

- A **Devices** entry sits in the left sidebar, right after Queue manager
  (`Ctrl+5`). It lists paired phones and linked PCs, whether each is online,
  and has **Pair a phone or PC** and **Link to another PC**.
- For a paired phone: send it a link, see its downloads live (progress, speed, time
  left) and Pause, Resume, Cancel, Retry or Remove them, or choose **Download on
  this PC instead**. Each command reports its result in plain words, including
  "The phone did not answer". Phones that don't share their downloads, or run an
  older app, say so.
- Settings, Phone keeps the phone-remote on/off switch and the port, and links to
  Devices. Pairing and the list of devices moved to Devices.

## Linking PCs

- **Link to another PC** connects this GrabLine to GrabLine on another PC (for
  example Windows and Linux) the way a phone pairs: type the address and the code
  the other PC shows under **Pair a phone or PC**. The other PC asks before
  allowing it. One link gives control both ways.
- A linked PC's downloads show live with the same controls, plus a box to send it
  a link. A PC linked both ways shows once; Remove asks which side to remove.
- **Let linked PCs see and control downloads on this PC** is a Settings switch, on
  by default. Linked PCs and phones reach this PC only over the same private-address
  rules as before; nothing listens on the internet.
- Protocol section 21 and the optional `deviceKind` and `clientPcId` fields in
  `pair` and `auth` describe the link; `PROTOCOL_VERSION` stays 6, so GrabLine for
  Android and older builds keep working. Section 20 (`phoneJobs`) lets a phone or a
  linked PC report its downloads and run commands from this PC.

## Look and feel

- The accent is the logo blue (`#2563EB`) in light and dark mode, with the website's
  dark palette, IBM Plex Sans and Plex Mono (SIL OFL, bundled), and 6 px rounded
  buttons and fields, to match GrabLine for Android and the website. See
  `docs/BRAND.md`.
- Checked checkboxes show a white tick and unchecked ones have a visible outline.
- The Advanced toggle, number fields and the pairing window were tidied; the status
  bar says "1 item".

## Security

- Phone and PC strings are shown as plain text everywhere, including tooltips, so a
  download name that looks like HTML can't load anything. Direction-control
  characters in names are neutralised.
- Lists from phones and PCs are validated and bounded, held in memory only, and
  never logged. Commands are rate-limited and time out; removing a device drops its
  list and any pending commands at once.
- A linked PC pins the other PC's key only after the pairing proof verifies, keeps
  one private key per link (mode 0600 on Linux and macOS; the user's profile folder
  permissions on Windows), and only connects to private-address IP literals.
- The new code was reviewed twice (a first pass found real problems, all fixed).
  The reviews ran on Opus; the Fable review the repository's rules ask for could
  not run because that account had no credits, and is still owed.

## Verification scope

- Full desktop suite, lint, formatting, mypy and the listen-only check pass;
  CI passes on Linux, Windows and macOS.
- Pairing and control were run for real between this desktop app (from source) and
  GrabLine for Android on a Redmi 12 over USB (`adb reverse`). Two linked PC
  instances were tested in-process over real TLS sockets, not on two physical PCs.

Not verified: linking two physical PCs over Wi-Fi through a firewall, the phone
paired with two desktops at once, and the Linux and macOS GUIs. Builds remain
unsigned.
