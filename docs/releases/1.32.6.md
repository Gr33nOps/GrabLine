# GrabLine 1.32.6

Browser-verified downloads now stay in the browser when the destination has a
Cloudflare clearance cookie. Previously GrabLine Connect cancelled the browser
transfer once the desktop app merely queued the URL. A separate HTTP client may
not be able to reuse the browser verification, leaving a failed HTTP 403 job
instead of the browser's working download.

Both Chromium download interception and Firefox response interception now
preserve that browser transfer. The browser download UI remains visible, and
ordinary downloads continue to be handed to GrabLine. If cookie metadata cannot
be read, interception conservatively leaves the download in the browser.

The HTTP 403 message now mentions browser verification and expired links as well
as sign-in, and explains how to disable interception for browser-only downloads.

## Verify

1. Update **GrabLine Connect** to 1.32.6 (updating only the desktop app is not
   enough), and update the desktop app for the improved error message.
2. Reload the website and complete its verification yourself in your browser.
3. Click the website's final download button. If the host uses a clearance
   cookie, the download should continue in the browser's Downloads list without
   being cancelled or creating a failed GrabLine job.
4. Try an ordinary file download to confirm GrabLine still captures it.

This is a browser-preserving fallback, not a claim that the desktop app can
bypass or inherit security verification. Live testing on the supplied ROM site
remains blocked by the browser tool's site-safety policy. Regression tests use
simulated browser events and cookie metadata without contacting that site.
