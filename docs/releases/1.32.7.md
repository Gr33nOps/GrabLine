# GrabLine 1.32.7

Files generated in ChatGPT, Claude, Gemini, and Google AI Studio now stay in the
browser during automatic download interception. Their file URLs can be tied to
the chat's browser session or generated as `blob:` URLs, so cancelling the
browser transfer and re-requesting the URL in GrabLine could fail.

The extension checks the download's referrer or originating tab before takeover
in Chromium and Firefox, leaves those chat downloads running, and shows the
browser Downloads UI. Downloads from other sites still use GrabLine normally.
`blob:`, `data:`, and other browser-generated URLs also remain in the browser
even if a browser reports an HTTP final URL.

## Verify

1. Update GrabLine Connect to 1.32.7 and reload the ChatGPT, Claude, or Gemini
   tab. Download a generated PDF or other attachment. It should complete in
   the browser Downloads list without a failed GrabLine job.
2. Download an ordinary file from another site. GrabLine should still take it
   over when interception is enabled.
3. If a chat attachment was generated before updating, generate or download it
   again; temporary URLs can expire.

Regression tests cover each chat's host, absent referrers, Chromium and Firefox
interception, and browser-generated URLs. No live account downloads were used.
