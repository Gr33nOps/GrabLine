# GrabLine 1.32.13

Security update: browser session credentials now remain scoped to their original host throughout direct downloads, resolution, redirects, retries and resume. Requests to a cached download destination no longer reapply the source website's Cookie, Authorization or Proxy-Authorization header. Same-host authenticated redirects continue to work, and destination servers can still establish their own cookie sessions.

The same boundary is enforced when switching mirrors, selecting fallback streams, and transforming cloud share links. Credentialed Smart downloads use a cookie-policy-aware native transport; browser cookies are excluded from media metadata and remote FFmpeg exports. Authenticated native HLS downloads remain supported. Remote FFmpeg-only inputs that require browser cookies may fail safely.

Thanks to [@caerrot](https://github.com/caerrot) for privately reporting the v1.32.12 download credential leak and providing a synthetic reproduction. GitHub private vulnerability reporting is now enabled for GrabLine.

Upgrade the desktop app to receive the security fix. Chrome and Firefox extension ZIPs are versioned 1.32.13 to match this release; the enforcement lives in the desktop app.
