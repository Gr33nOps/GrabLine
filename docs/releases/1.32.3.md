# GrabLine 1.32.3

Fixed a Windows error that could prevent the YouTube hover-button quality panel
and media downloads from starting: `WinError 448` on an untrusted PATH mount
such as `C:\msys64\ucrt64\bin`.

GrabLine now explicitly disables yt-dlp's implicit JavaScript-runtime discovery
when no runtime is requested or available. Runtime-enabled extraction continues
to use the explicit Deno/Node path selected by GrabLine, including its managed
Deno installation. This applies to metadata analysis, downloads, and warm-up;
it does not modify Windows PATH or relax mount-point security.

Existing fragment concurrency, metadata reuse, quality selection, merging,
audio conversion, browser-session handling, and resume behavior are preserved.
Regression coverage reproduces failing runtime discovery and checks real MP3,
M4A, and FLAC conversion for playable audio and complete duration, alongside
existing direct media, HLS/DASH, merge, cancellation, and resume tests.

## Verify

1. Update the desktop app to 1.32.3 and reload the YouTube page.
2. Use the hover download button on a public video and choose a quality.
   The quality panel should open without WinError 448.
3. Download a video and an audio-only version; check playback, audio, and duration.
4. Try a Short and another supported media site, plus pause/resume on a longer file.

Live YouTube checks from the development environment encountered an unavailable
video and a sign-in/bot challenge. Successful live YouTube downloading therefore
remains to be verified on the user's machine. Private, removed, region-restricted,
DRM-protected, or login-gated media cannot be guaranteed; network and site limits
also determine download speed.
