# GrabLine 1.32.8

Automatic browser download takeover now has a fallback for **all websites**.
The extension pauses the browser's download while GrabLine works. It resumes
that original browser download if the desktop job fails, the app closes, the
native host disappears, or no desktop job starts within 90 seconds. The browser
item is cancelled only after GrabLine reports that its new job completed.

This fixes the handoff gap where a site refused GrabLine's separate HTTP
request but the browser's original transfer had already been cancelled.
Firefox now uses the same recoverable download path as Chromium; blocking
network interception was removed because it could not be resumed after a
desktop failure. Chat-generated and browser-only files still stay in the
browser immediately.

## Verify

1. Install GrabLine and GrabLine Connect 1.32.8, enable browser takeover, and
   download an ordinary file. GrabLine should finish it; the paused browser
   item should then disappear.
2. Try a site that fails in GrabLine but downloads in the browser. After the
   GrabLine job fails, the original browser download should resume. It should
   also resume if GrabLine closes during the transfer.
3. Download a generated ChatGPT, Claude, or Gemini attachment. It should stay
   in the browser as before.

The fallback still depends on the browser being able to resume the site's URL;
an expired URL or a server that rejects the browser too cannot be repaired by
the extension. Regression tests cover the handoff, older job history, failure,
success, native-host loss, and the timeout path.
